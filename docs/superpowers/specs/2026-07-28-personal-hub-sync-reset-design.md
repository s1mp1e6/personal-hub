# Personal Hub 可靠同步与重置设计

日期：2026-07-28

## 目标

让同一用户在手机、平板和电脑之间快速、安全地同步本地数据。正常变更自动合并，真正冲突交给用户决定；任何同步或重置失败都不能破坏原数据。

## 本轮范围

- GitHub Pages 继续托管静态前端。
- Cloudflare Worker 与 Durable Object 只负责短码配对和临时 WebRTC 信令。
- 数据与附件通过 WebRTC 点对点传输，不存入 Cloudflare。
- 增加逐记录版本判断、选择性同步、冲突兜底、同步恢复点。
- 增加摄像头授权引导、相册二维码识别和配对码回退。
- 将重置拆分为“日常清理”和“数据重置”。

## 非目标

- 不加入账号、多人协作或后台自动同步。
- 不把个人数据保存到云端。
- 不在本轮接入 GitHub Gist。
- 不承诺在没有 TURN 服务时连接所有受限网络；失败时保留离线配对码。

## 部署架构

1. GitHub Pages 发布 `site/`。
2. Cloudflare Worker 提供创建房间、加入房间和 WebSocket 升级入口。
3. 每个 Durable Object 仅保存一个短期房间的信令消息，空闲或创建 5 分钟后销毁。
4. 房间码用于定位临时房间；二维码额外包含一次性加入令牌。
5. 手动输入房间码的设备连接后，双方显示相同的安全校验短语，用户确认后才可交换清单和数据。
6. Cloudflare 不接收备份正文、附件、记录标题或用户内容。

## 数据版本模型

每台设备在 IndexedDB 中保存稳定的随机 `deviceId`。每条记录、模块元数据、桌面布局和可同步设置包含内部同步信息：

```json
{
  "vector": { "device-id": 3 },
  "contentHash": "sha256...",
  "deleted": false,
  "conflictOf": null
}
```

- 本地创建或修改时递增本设备在版本向量中的计数。
- 旧记录首次加载时补充空向量和内容哈希，不改变用户可见数据。
- 内容相同但向量不同的记录视为相同，并合并向量。
- 一方向量支配另一方时，支配方是明确的新版本。
- 两方向量互不支配且内容不同，视为并发冲突，不使用设备系统时间裁决。
- 删除保存为轻量 tombstone，防止旧设备在后续同步时使数据复活。
- 冲突副本使用新 ID，并通过 `conflictOf` 指向原记录。

附件使用 SHA-256 标识。相同哈希只保存一份；传输完成后验证大小和哈希，验证失败不提交同步。

## 同步流程

### 1. 连接设备

- 用户选择“创建同步”或“加入同步”。
- 创建方展示短房间码、二维码、过期倒计时和离线配对入口。
- 加入方可扫码、从相册识别二维码、输入房间码或粘贴离线配对码。
- WebRTC 建立后双方确认安全校验短语。

### 2. 比较清单

双方只交换模块、记录 ID、版本向量、内容哈希、删除标记和附件摘要。界面按以下类别汇总：

- 新增
- 明确更新
- 并发冲突
- 待确认删除
- 相同并跳过
- 缺失或异常附件

发送方先选择可发送的模块、附件和设置；接收方可在该范围内进一步取消。双方均提供全部选择、全部取消、分类选择、记录数和预计传输大小。

### 3. 生成合并计划

默认“安全同步”使用以下规则：

| 情况 | 默认处理 |
| --- | --- |
| 两端内容相同 | 跳过并合并版本向量 |
| 仅发送端存在 | 新增到接收端 |
| 仅接收端存在 | 保留接收端 |
| 发送端版本明确更新 | 更新接收端 |
| 接收端版本明确更新 | 保留接收端 |
| 两端并发修改 | 保留接收端，发送端保存为同步副本 |
| 发送端删除、接收端未修改 | 放入待确认删除，默认不勾选 |
| 一端删除、另一端修改 | 保留修改版本并标记冲突 |
| 附件缺失或校验失败 | 不提交相关记录，允许重试 |

用户可展开“自定义同步”，修改冲突和删除项目的处理方式。

### 4. 传输与提交

- 同步前创建恢复点。
- 数据按块传输，每块带序号和校验信息，并支持确认与有限重试。
- 接收方先在内存中构建合并结果，附件写入临时记录。
- 所有校验通过后，使用覆盖状态与附件存储的同一个 IndexedDB 事务提交。
- 中断、超时、空间不足或校验失败时放弃临时结果，原数据保持不变。
- 结果页显示新增、更新、冲突副本、删除、跳过和失败统计，并提供撤销本次同步。

## 恢复点

- 同步和破坏性重置前自动创建恢复点。
- 只复制状态 JSON；附件 Blob 保持不可变并按引用计数保留，避免重复占用空间。
- 默认保留最近 3 个恢复点。
- 删除恢复点或清理失效附件时，只有没有当前数据和恢复点引用的 Blob 才能删除。

## 摄像头与二维码

- 首次点击扫码时先显示应用内说明，明确相机只用于本机识别二维码。
- 用户点击继续后才调用浏览器摄像头 API；浏览器原生权限提示不能被网页替代。
- 拒绝授权后显示针对当前浏览器的重新授权说明。
- 始终提供“从相册选择二维码”和“粘贴配对码”。
- 相册图片通过本地 `jsQR` 解码，不上传。
- 摄像头画面启动后检测视频尺寸；无画面时给出切换权限、相册识别和粘贴码入口。

## 重置中心

### 日常清理

- 已完成任务
- 已归档内容
- 无任何数据或恢复点引用的附件

### 数据重置

- 用户勾选一个或多个模块
- 主题与外观设置
- 桌面布局
- 同步设备信息
- 全部本机数据

两类操作均显示影响数量并支持全选/取消全选。执行前创建恢复点；全部本机数据需要二次确认。清理动作产生 tombstone，避免被其他设备的旧数据自动恢复；恢复点还原后会形成新的本地版本，而不是回退版本向量。

## 错误与安全处理

- 房间过期、令牌错误、应用版本不兼容和安全短语未确认时禁止传输。
- 房间接口限制创建和加入频率，避免短码被批量猜测。
- 同步协议带版本号；不兼容时停止并建议更新应用或使用备份文件。
- 配对日志只记录状态、耗时和错误码，不记录用户内容或完整配对凭据。
- 离线配对码继续使用压缩格式，并在解析前校验前缀、类型、长度和协议版本。
- 所有接收数据先做结构、大小、模块白名单和附件数量校验。

## 测试与验收

- 单元测试覆盖版本向量比较、清单分类、合并计划、tombstone、冲突副本和附件去重。
- 两个隔离浏览器上下文验证新增、单边修改、并发修改、删除冲突和选择性模块同步。
- 注入中断、重复数据块、缺失数据块、错误哈希和存储失败，确认接收端无部分提交。
- 验证房间过期、错误令牌、错误配对码、协议版本不兼容和离线配对回退。
- 验证首次摄像头说明、授权允许、授权拒绝、无视频画面和相册二维码。
- 验证日常清理、按模块重置、全部重置、恢复点创建和撤销。
- 在 1365、834、390 和 360 像素宽度执行响应式与横向溢出检查。
- 部署后在 GitHub Pages HTTPS 地址执行两端连接、清单比较、数据传输、Service Worker 和控制台错误检查。

## Gist 决策

Gist 不参与本轮实现。未来如增加 GitHub 登录，可将“客户端加密后的手动备份”作为独立功能评估；它不能替代同步协议、附件存储或冲突处理。
